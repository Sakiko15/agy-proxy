# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`agy-proxy` is a self-hosted LLM gateway: it spawns the **official, unmodified** Google Antigravity `agy` CLI (`agy -p --output-format stream-json`) as the upstream engine and exposes **OpenAI Chat Completions** + **Anthropic Messages** compatible HTTP APIs with per-key quotas and a management WebUI. Runs in Docker on a VPS behind a reverse proxy. TypeScript ESM, Node ≥ 24, strict mode with `.ts` import extensions.

**The three source-of-truth documents — read them before any work:**
- `docs/charter.md` — 立项文档: architecture, protocol support matrix (§4), module porting list (§5), stability/perf design, tech stack (§8), security rules (§10)
- `docs/development.md` — dev process: porting discipline, PR DoD, release rules, security red lines
- `docs/acceptance.md` — per-milestone acceptance criteria (M0–M5) + golden test case spec (§2)

## Commands

```bash
npm run check   # tsc --noEmit (strict, zero-tolerance)
npm run build   # tsdown → dist/
npm test        # vitest run
npm run dev     # tsx src/index.ts
```

- CI gates run check → build → test **in that order** (`.github/workflows/ci.yml`).
- Single test file: `npx vitest run test/m0.test.ts`; by name: `npx vitest run -t "pattern"`.
- WebUI lives in `web/` (separate npm project, own lockfile): `npm run web:dev` (Vite proxies /admin,/v1 to a local gateway), `npm run web:build`, `npm run web:test`, `npm run web:check`. Root `build` chains tsdown + web build. Web TS uses the same strict style (`.ts` import extensions, `noUncheckedIndexedAccess`); all user-facing CJK lives in `web/src/i18n/zh-CN.ts`/`en.ts` (never `.tsx` — acceptance greps scan only `.tsx`); zh/en key identity is enforced by `web/src/i18n/completeness.test.ts`.

## Key facts that shape the code

- **Config layering** (`src/common/config.ts`): env (`AGY_PROXY_*`, read per call) > `~/.agy-proxy/gateway/runtime-overrides.json` (or `$AGY_PROXY_DATA_DIR`) > defaults. `permissionMode` default is **`plan`** — `skip` means `--dangerously-skip-permissions` (arbitrary shell in container); its default must never be flipped casually (development.md §8).
- **agy quirks already handled in runner.ts**: stdin closed immediately (agy hangs forever on open pipe stdin), activity-based watchdog re-armed on every stdout/stderr chunk, whole-process-group kill (`process.kill(-pid)` on POSIX, `taskkill /T /F` on Windows), Windows cmd-shim re-spawn through `cmd.exe` with verbatim args, `isolatedHomeEnv` sets `USERPROFILE`/`HOMEDRIVE`/`HOMEPATH` (not just `HOME`) on Windows.
- **Engine error codes** (`src/common/types.ts` `Err`): AUTH / AGY_NOT_INSTALLED / TIMEOUT / PROCESS_EXIT / INVALID_OUTPUT / AGY_ERROR / BUSY / POOL_EXHAUSTED (429 + Retry-After = earliest reset countdown) / VALIDATION_REQUIRED (403, passthrough message carries `validation_url`) / … — protocol adapters map these onto OpenAI (`{error:{message,type,code}}`) and Anthropic (`{type:'error',error:{type,message}}`) bodies. Real agy error text is always surfaced verbatim, never replaced by generic "exited with code 1".
- **Ledger accounting**: one SQLite row per actual agy spawn via `EngineDeps.onRun` (fires at settlement — later than the client stream ends on tool-cut spans; continuations and pre-flight rejects never book a row). `EngineCall.meta` = `{reqId: x-request-id ?? fastify req.id, keyId, protocol}`; the `request_id UNIQUE + INSERT OR IGNORE` contract makes same-id replays idempotent.
- **All persistent state under `dataDir()`** (`AGY_PROXY_DATA_DIR`, default `~/.agy-proxy`): pool, sessions, per-account isolated HOMEs, media, SQLite (`<dataDir>/agy-proxy.db` unless `AGY_PROXY_DB_PATH`). Account credentials are device-bound — everything must live on the Docker volume.
- **No systemHome accounts**: unlike dsh-agy-link, every pool account uses an isolated HOME (VPS has no desktop login).
- **Hard-rate-limit in-flight semantics (M3, user decision)**: an in-flight hard 429 fails that request and cools the account; the NEXT request auto-switches. No in-flight transparent replay in v1 (charter §6 amended). Soft limits never change account state. **M5 复议定案：维持本决策** — the engine-level single retry (below) is orthogonal: it covers only failures that produced nothing on the wire, never mid-span replay.
- **Admin push surface (M4)**: `src/server/events.ts` `AdminEventBus` — seq-stamped events (`snapshot`/`run`/`pool`), 200-event ring, `Last-Event-ID` replay is snapshot XOR replay (never both). Snapshots are client-local (ring-recorded, NOT broadcast) — the route delivers them explicitly. Pool mutations stream via the `AccountPoolManager.onChange` hook (one `notify()` at the end of `persist()`, the only ported-file edit in M4); run events reuse the exact ledger fields from the `onRun` hook. `closeAll()` must be called in shutdown teardown — `app.close()` does not end hijacked connections.
- **Static hosting (M4)**: `src/server/static.ts` — `wildcard:false` per-file routes + SPA fallback inside the single not-found handler (dot-free GET non-API only); `cacheControl:false` owns every cache decision. No `web/dist` → JSON-only no-op; `AGY_PROXY_WEB_DIST` (config `webDist`) overrides detection. Settings UI writes `runtime-overrides.json` atomically via `src/server/settings.ts` (9-key allowlist; env-locked keys are *reported* via `envLocked`, written to the file anyway).
- **Engine-level single retry (M5)**: `stream()` is a dispatch-level for(;;) loop — one recording per LOGICAL run, appended across attempts; `rec.settle` fires exactly once (a failure frame can never reach the client before retries are exhausted). Retry gate = `RETRYABLE_CODES` (TIMEOUT / PROCESS_EXIT / no-result INVALID_OUTPUT) + shapeOnly guard && `!rec.hasClientMappedEvents()` (recording.ts getter — step events only). NEVER run the retry inside the account-queue task (awaiting another queue under concurrency:1 deadlocks). The retry loop must never book usage per attempt: `onRun` carries `{attempt, final, failureMessage?}` and only `final` books/publishes (`INSERT OR IGNORE` is first-wins — an attempt-0 failure row would swallow the retry's successful usage). `EngineDeps.retryDelay?` is injectable — tests that don't want the policy delay must inject it or the suite sleeps 2s per retry.
- **Busy-aware selection (M5)**: `pool.selectAccount(family, busy?)` skips accounts with in-flight runs; the engine tracks them (busyAccounts set) until the dispatch finally. Without this, concurrent same-family arrivals all stack onto candidates[0]'s queue (measured 0.9× throughput where ≥2.5× is the acceptance bar).
- **Schema v2 + flush fault tolerance (M5)**: `db.ts` SCHEMA_VERSION=2 adds `usage.error_text` via a `PRAGMA table_info`-guarded ALTER (v1 DBs upgrade in place, rows preserved). `usage-ledger.flush()` catches transaction failures and requeues (time-ordered merge, `MAX_PENDING_ROWS=5000` keeps newest, oldest dropped), warns at most once per 60s — a failed `void`-flush chain used to be an unhandled rejection that killed the process on disk-full. `close()` is fully guarded (never throws, still checkpoints).
- **Client-boundary token scrub (M5)**: `scrubTokenMaterial()` (diagnostics.ts — narrow: `ya29.*` / Bearer / length-anchored `4/` codes, URLs untouched) is wired ONLY at `EventMapper.emitFailure` (the single terminal-failure funnel to both protocols). Deliberately NOT `redactLine()` — it mangles URLs and would destroy the validation_url feature passthrough. Log-side redaction stays on redactLine.
- **Media sweeper (M5)**: `src/host/media-sweeper.ts` `startMediaSweeper(dir, ttlMs, intervalMs, log)` — media.ts is a verbatim port and must stay diffable, so the scheduling lives in a new file; wired at boot + hourly interval, `mediaTtlMs <= 0` disables.
- **Docker (M5)**: Dockerfile pins `ARG AGY_CLI_VERSION=1.1.22` (m1.md real-binary record) — never revert to floating tags; `docker-compose.yml` carries tini/init, `stop_grace_period: 30s`, named volume, loopback publish, healthcheck. Deployment runbook: `docs/deploy.md`.

## Testing

- Golden cases run against a keyless or env-key auth posture — the golden runner never touches the keys table; key/pool/ledger behavior lives in dedicated suites (`auth-keys`, `admin-api`, `pool-gateway`, `key-store`, `usage-ledger`, `db`).
- Golden-case system (acceptance.md §2): `test/golden/<protocol>/<case>/` (openai/, anthropic/, models/) with `request.json` (raw body = legacy /v1/chat/completions POST, or `{method,url,query,headers,body}`) + `events.ndjson` (fake-agy `FAKE_AGY_EVENTS_FILE` verbatim replay; empty = no spawn) + `expected.json` (`_status` pins HTTP status; `sse` array for streaming cases) + `PROVENANCE.md`; every case must cite its source (OpenAI SDK path / Anthropic docs URL — the runner asserts a URL is present). Provenance convention: JSON cannot carry comments, so the citation lives in a sibling `PROVENANCE.md` plus an `_provenance` key in expected.json (stripped by the runner). Dynamic fields use sentinels: `chatcmpl-/msg_ ids → __ID__` (shape-regex checked), `agytc- mirror ids → __AGYTC__`, embedded run UUIDs → `__UUID__` (scrubbed at RAW text level pre-parse — they live inside JSON strings), `created → 0` on chat surfaces only, MODEL_CREATED (1767225600) compared literally on model listings. Per-case `case.json`: `apiKey`, `fakeAgyExitCode`, `discoveredModels`. `sseHeartbeatMs: 0` in the runner keeps SSE deterministic. Windows: temp-dir cleanup after each case is best-effort (fake-agy child can hold a handle a beat past exit).
- fake-agy is the only upstream for tests — never hit real Google endpoints in CI. Modes: `ok|auth|noise|exit12|exit-error|real|real-error|real-fail|hang|slow|rate-limit|validation|kill-early|kill-mid|flood` plus `FAKE_AGY_EVENTS_FILE` (verbatim replay, with `FAKE_AGY_EXIT_CODE`), `FAKE_AGY_ARGS_FILE` (argv recording), `FAKE_AGY_FAIL_HOME` (hard-fails only the account whose isolated HOME matches — pool switch drills) and `FAKE_AGY_MODE_FILE` (mode re-read per process start — flip failure modes between retry attempts mid-run; falls back to `FAKE_AGY_MODE`). kill-* modes self-SIGKILL (win32 records exit code 1 / no signal, POSIX a SIGKILL signal — both classify as PROCESS_EXIT).
